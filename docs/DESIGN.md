# Design

Invariants, decisions and their rationale. Pending work lives in `ROADMAP.md`.

## Components

- **Scramble**: per-character text scramble of an element's plain text; child elements are replaced (documented, warned in development builds). Palette colours, vertical jitter, skew, RGB split (`text-shadow` from `palette[0]`/`palette[1]`), glow, flicker, up to 8 glitch lines, whole-label sync slip, rolling scanlines, phosphor-decay transition on lock. Lock orders: `ltr`, `rtl`, `center`, `random`. One cell per grapheme cluster (`Intl.Segmenter`, code points without it), so accented letters and emoji with modifiers stay whole. Joined scripts (Arabic, Devanagari) lose their joining: each cell is shaped on its own.
- **Glitch**: canvas overlay for an `<img>`. R/G/B channels are separated once and recombined additively at offsets; slice tears; block moves (sometimes single-channel); palette lines and tinted bands; frame shake and flicker via CSS; scanlines. Honours `object-fit` (`fill`, `cover`, `contain`, `scale-down`, `none`) and `object-position`. The overlay covers the img content box (inside borders and padding) with the matching inner corner radii. An img inside `<picture>` stays its child (otherwise `<source>` selection stops); the wrapper goes around the `<picture>`, and the overlay offset is measured through it. The img's `transform`, `translate`, `rotate` and `scale` are mirrored onto the overlay, with the origin shifted from the border box to the content box; they are re-read every animation frame while the overlay is visible, so a hover zoom transition stays aligned. Not mirrored: a non-default `transform-box` (browsers report the origin against the border box even when rendering against another box) and transforms on a wrapping `<picture>`. Buffers (base, R, G, B, visible canvas) are built on the first `play()`/`burst()` at 1 canvas px per CSS px regardless of `devicePixelRatio`, and released after 30 s idle or on resize: a glitch frame is on screen for a fraction of a second, so full DPR is not worth 4x the memory (about 4 MB instead of 17 MB for a 700 px wide 16:9 image at DPR 2), and images that glitch rarely do not hold memory. Repeated glitches within 30 s reuse the buffers; a rebuild costs a few ms.
- **Ambient**: micro-glitch scheduler over any mix of Scramble and Glitch instances. Intervals are exponentially distributed (Poisson process); `rate` is events per minute across all targets. Each event calls `burst({ amount, count, duration, intensity })` on a random target that is not `running`.

## Invariants

1. **Layout never moves.** Text: each character is a cell sized by an invisible `::before` copy of the real glyph, and the animated glyph is absolutely positioned inside it. A monospace font alone is not enough: fallback glyphs (such as `≤`) and font switches change advance widths. Images: the `<img>` is untouched; a canvas overlay sits exactly over it and is visible only while live.
2. **No pixel reads on images.** Channels are separated with compositing (`multiply` + `destination-in`) and recombined with `lighter`. `getImageData` is never used: it throws on cross-origin images (tainted canvas), and avoiding it is what lets the effect work without CORS.
3. **JS writes custom properties, CSS renders.** Text animation only changes the text of absolutely positioned glyphs (the data of one text node per glyph, created once, so no nodes are added or removed while animating) and CSS variables consumed by `transform`, `opacity`, `text-shadow` and `color`. Updates are stepped at `fps`, which is what makes motion read as analog rather than smooth.
4. **Accessibility.** The real label is in a visually hidden `.nf-text-sr` span; animated layers are `aria-hidden`; the visible row is `user-select:none`, so copying a label yields it once (from the hidden span; the selection highlight is not visible); `prefers-reduced-motion` disables playback and hides overlays.
5. **Zero runtime dependencies.** A single `<script>` tag must work for consumers. Build tooling in the repo is fine; it is a dev dependency, not shipped.
6. **MIT only.** No GSAP or other non-OSI-licensed code (see "Build vs reuse").

## Decisions

### Build vs reuse

| Option | Licence | Fit | Verdict |
|---|---|---|---|
| GSAP ScrambleTextPlugin | GSAP "no charge" licence (free for commercial use since 3.13), not OSI; restricts use in tools competing with Webflow | Tweens one `textContent` string; per-character colour and jitter would need SplitText plus per-character tweens | Rejected: licence |
| baffle.js | MIT | Also writes one string; unmaintained since about 2016; the reusable core is about 40 lines | Rejected: nothing worth keeping |
| Own implementation | MIT | Per-character DOM is required for the effects anyway | Chosen |

### Language: strict TypeScript

TypeScript source, built into ESM, CJS, a browser global bundle and `.d.ts`. Rationale: consumers get generated, always-correct types for a large option surface (text options, image options, burst arguments, bind options); the compiler catches option typos, nullable canvas contexts and px vs ratio mix-ups between text and image options; refactors are safe for contributors. Cost: a build step, which affects only the repo, not the published artefact.

Build: `tsdown` produces `dist/noisefloor.js` (ESM), `dist/noisefloor.cjs`, `dist/noisefloor.iife.js` (minified IIFE, `Noisefloor` global, the `unpkg`/`jsdelivr` entry) and `.d.ts`/`.d.cts`, all targeting the supported browsers: Safari 16, Chrome and Edge 107, Firefox 104 (Vite's default build target, Baseline widely available 2025), so no syntax is rewritten (`tsconfig`: ES2022). This floor covers every desktop browser still receiving updates and iPhones back to the 8 and X (iOS 16); devices stuck on iOS 15 are the iPhone 6s and 7. An older floor gains almost no users (every device that ran iOS 14 also runs iOS 15) and failure is benign: the effects are decoration, and without them labels and images show unchanged. Bundler users are unaffected either way, since their bundler applies its own target. tsdown rather than tsup: tsup is unmaintained and pins esbuild 0.27 (known advisory) and TypeScript below 7.

Effects are ES classes, so constructors require `new`. Each class's `defaults` is frozen, including its palette array; instances copy it. `defaults` is a static getter, not a static field: a class whose body has only methods and accessors is side-effect free for bundlers, so an unused effect is dropped from a single-effect import, whatever the build target (a field lowered for an older target becomes an assignment after the class, which bundlers keep). `scripts/treeshake.mjs` checks this.

Options are validated on construction and on `set()`/`burst()`: numbers outside their range are clamped, non-numbers and empty `chars`/`palette` fall back to defaults. `set()` is the only way in: `options` returns a frozen copy of the validated values (what is actually used, fallbacks included), palettes are stored as frozen copies so later changes to the caller's array have no effect, and `Glitch.ready` is a getter. `burst()` takes only an options object; a non-object argument is ignored with a development warning. Warnings (`console.warn`, once per option) are emitted only in development builds: each site reads `process.env.NODE_ENV !== 'production'` inline, inside a `try`, behind `!__NF_IIFE__`. A consumer's bundler replaces `process.env.NODE_ENV` and its minifier then drops the branch with its message (verified with esbuild, Rollup with terser, Vite and webpack 5; a Vite library-mode build leaves `process.env.NODE_ENV` alone by design, so only app builds strip). Without a bundler `process` is undefined, the `try` swallows the ReferenceError, and there are no warnings; importing in Node or an unbundled browser does not throw. The IIFE bundle compiles the sites out (`__NF_IIFE__` build constant). `tsdown.config.ts` maps `process.env.NODE_ENV` to itself, because rolldown otherwise replaces it in `platform: 'browser'` builds. Two choices that look simpler were rejected: a shared `DEV` constant or `isDev()` function (a runtime value or call that minifiers do not fold, and `typeof process !== 'undefined'` guards read false in a browser dev server, which hides the warnings in Vite and webpack development), and separate `development`/`production` files behind export conditions (a second copy of the library in `dist/`, and esbuild and Rollup do not set those conditions without configuration, so the default build would still ship the warnings).

Considered and rejected: JS with JSDoc types and `checkJs`. It gives type checking and generated `.d.ts` without compiling, which suits projects that must stay build-free. This one does not need to.

### Naming

- **Package and repo: `noisefloor`.** npm `noisefloor` (unscoped), repo `github.com/digitalemagine/noisefloor`. RF term for the level where signal dissolves into interference; distinctive, searchable, and an umbrella for several effects rather than a description of one.
- **No language suffix** (`-js`, `-ts`). Repo and package names match, and the source language is an implementation detail exposed through shipped types. In the ecosystem `-ts` suggests a port or binding of a project that exists elsewhere.
- **Unscoped.** The short name was free and the library is a single package. An unscoped package belongs to its maintainer account (`stefanocrosta`); the npm organization `digitalemagine` has read-write access to it (team `developers`), so it is listed under the organization and its members can maintain it. The `@digitalemagine` scope, held by that organization, is for future add-ons (for example framework wrappers).
- **Exports: `Scramble`, `Glitch`, `Ambient`, `version`.** The brand comes from the package name, so a `Signal` prefix on classes is redundant. Browser global: one namespace object, `Noisefloor` (`Noisefloor.Scramble`, ...). No per-class globals.
- **Rejected names:** `signal-fx` (collides with SignalFx, Splunk's observability product; npm `signalfx` is theirs); `signalscramble` / `signalglitch` (each names one effect, generic words are crowded on npm, and "signals" also means framework reactivity in JS).

### Text changes and typing

- **Typing is a Scramble mode, not a new effect.** It is the same cell DOM, options, lifecycle, `burst()` and Ambient support; only the per-cell timing differs (an appear time before the lock time). A separate class would duplicate Scramble.
- **Typing never reflows.** All cells are sized from the final text before anything appears; only glyphs are revealed.
- **Typing timing:** `reveal: 'type'` gives each cell an appear time `show = rank x (duration - trail)` and a lock time `show + trail` (`trail` clamped to `duration`), so the last character locks at `duration` and `order` decides the sequence (`ltr` typewriter, `random` decrypt, `center` outward). Before `show` the glyph is empty; spaces lock as they appear. `burst()` ignores `reveal`.
- **Typing speed:** `speed` > 0 (characters per second) replaces `duration` for typed runs: the run lasts `(n - 1) / speed + trail` for `n` cells, so for `ltr`/`rtl` one character appears every `1 / speed` s and a longer label takes longer, as in typewriter effects elsewhere. It is a separate option rather than a unit on `duration` so a config can switch `reveal` without rescaling, and the default 0 keeps the fitted run. Pacing is per rank, so `center` (two cells per rank) and `random` keep the run length but not a per-character interval. The all-at-once reveal ignores it.
- **Caret:** `cursor: true` draws a block caret as `::after` of the most recently appeared cell, absolutely positioned after it (before it for `rtl`), so it never affects layout; it follows the typing head for every `order`, takes the text colour (`--nf-cursor` overrides) and the `glow` option, jitters by half of `jitter`, and is removed when the run ends.
- **Length changes snap at the start.** When the new text has a different length, cells are rebuilt from it when the transition begins, so width changes once, then nothing moves. Rejected for now: reserving the wider width until the end (`resize: 'end'`). It needs each cell as wide as the wider of its old and new character (both stacked invisibly, a change to the core layout trick), erase ordering for every `order`, and mid-transition `burst`/`finish`/`destroy` handling, for a case where the line still moves once. Adding it later needs from/to characters per cell; today a cell stores only its target.
- **The API is `play({ text })`**, not a separate `setText()`: changing the label is a transition, so it shares play's timing, `order`, `finished` and typing mode. `text` is a getter; a `data-text` attribute on the element is kept in sync so `destroy()` and a later instance see the current label.
- **Cycling words without movement:** reserve the widest word with `min-width` on the element; document this rather than adding an option.

### Bind triggers

- `trigger` is a DOM event name or `'visible'`. `'visible'` uses one IntersectionObserver per `bind()` call on the hosts, with a `-10%` bottom root margin rather than a ratio threshold, so a host taller than the viewport still plays and typing does not start at the very bottom edge. Hosts already in view play at bind time. Without IntersectionObserver, instances play once at bind time.
- `once: true` unbinds after the first play, for any trigger: a scroll reveal usually should not replay every time the user scrolls back.

### Frameworks: recipes, not wrappers

- React, Vue and Svelte are supported through documented recipes (README "Frameworks", site API section), not packages: three rules cover them. Render the label once and change it with `play({ text })`, so the framework never patches the text node Scramble replaced; wrap the img in a `data-nf-wrap` element, so Glitch does not move the img away from the parent the framework knows; create after mount, `destroy()` on unmount. Without them, a re-render corrupts the label and a sibling insert before a moved img throws in React.
- The recipes were checked against React 19 (StrictMode double mount), Vue 3.5 and Svelte 5: mount, hover, text change, unrelated re-render, sibling insert and removal before the image, src change, unmount, with no errors or framework warnings. Svelte needs `untrack` for the initial label (a plain read warns `state_referenced_locally`).

### Declarative markup: `noisefloor/auto`

- **Two styles, one core.** The JS API (`bind()` with any selector, or constructors) is the primary one and needs no markup changes. `data-nf` attributes are an opt-in layer for static pages and CMS content, where per-element options belong in the markup. Neither is promoted as better: JS gives typed options and explicit lifecycle, attributes give zero-script configuration.
- **A separate entry point, not part of the core.** Auto-init scans the document on import and keeps a MutationObserver, a side effect the core must not have (tree-shaking, SSR, pages that never use attributes). ESM/CJS: `noisefloor/auto`, sharing a chunk (`dist/core.*`, a fixed name rather than the hashed module name rolldown picks) with `noisefloor` so both see the same classes. Script tag: `noisefloor.auto.iife.js`, the full library plus `Noisefloor.auto` (IIFE output cannot share chunks), about 1 KB gzipped more than `noisefloor.iife.js`. `sideEffects` lists both, so bundlers keep a bare `import 'noisefloor/auto'`.
- **One attribute per option**, `data-nf-<option>`, typed by the effect's `defaults` (number, boolean, comma list for `palette`, string). Names match without dashes and case, because HTML lowercases attribute names: `data-nf-rgbSplit` arrives as `data-nf-rgbsplit`. Invalid values go through the same validation and dev warnings as JS options. Rejected: JSON in one attribute (exact names, but quoting is error-prone in HTML and templates). `palette` splits on commas outside parentheses, so `rgb(...)` colours survive.
- **Bind and Ambient attributes:** `data-nf-trigger` (as `bind()`, plus `none` for no trigger), `data-nf-once`, `data-nf-ambient` (one shared Ambient, created on first use, reachable through `ambient()`). There is no attribute for `host`: the default (closest link or button) covers the markup case.
- **Lifecycle follows the DOM.** The observer watches `childList` and the `data-nf` attribute on the whole document: added elements are set up, an instance is destroyed when its element is no longer connected when the records are delivered (so a move within the document keeps it), and changing `data-nf` rebuilds it. Other `data-nf-*` attributes are read once; change options with JS. This relies on effects not adding or removing nodes while animating (Scramble writes glyph text nodes in place), so the observer stays idle during playback. Elements that already have an instance are skipped, so JS-created instances win. Shadow roots are not observed; `scan(root)` sets them up.
- **Not for framework-rendered markup.** Auto-init would create instances whenever the framework renders and destroy them when it removes nodes, outside the framework's lifecycle; the framework recipes stay the supported route.

### Instance lifecycle

- **One instance per element; the newest wins.** Constructing Scramble or Glitch on an element that already has an instance destroys the old one first, then builds from the restored DOM. Covers HMR, SPA re-init and overlapping `bind()` selectors. Rejected: returning the existing instance, which would keep stale code after HMR and ignore the new options.
- The link is a property on the element under `Symbol.for('noisefloor.instance')`, not a module-level WeakMap, so it survives module re-evaluation and duplicate copies of the library.
- **Completion is a `finished` promise, WAAPI style**, not an `onComplete` callback: it composes with `await` and needs no option. It is pending while an animation runs and resolves with the instance when it ends; a `play()` restart keeps the pending promise; when idle it is already resolved. It resolves (never rejects) on `finish()` and `destroy()`, so awaiting it cannot produce unhandled rejections.
- `destroy()` is idempotent: a replaced instance may still be destroyed by the code that created it, and that must not touch its successor.
- After `destroy()`, `play`, `burst`, `set` and `finish` are no-ops and `destroyed` is true, for the same reason: the element may belong to a successor. Ambient drops destroyed targets on its next event; `Ambient.destroy()` stops it for good and does not destroy its targets.

## Positioning

One line: **analog-signal interference for UI.** Labels and images that break up like a weak signal, then recover; layout never moves, screen readers and reduced-motion users are unaffected, cross-origin images work without CORS.

Lead with what nobody else has: the Ambient scheduler (Poisson-timed micro-glitches across a whole page) and the per-character styled scramble. Do not lead with "image glitch": PowerGlitch owns "glitch any element in 2 KB".

## CSS injection

The base stylesheet has three parts: scanlines (shared), text (Scramble) and image (Glitch). Each effect passes its parts to `injectCSS`, so a single-effect bundle carries only its own rules; the parts are string concatenations, not `[].join()` calls, so an unused one is side-effect free and dropped. Per root there is one `<style data-noisefloor>`; a part another effect needs later is appended to it. Single-effect sizes (`scripts/treeshake.mjs`, esbuild production, gzip -9, 2026-11-13): Scramble 4.5 KB, Glitch 4.9 KB, Ambient 1.0 KB, everything 7.5 KB. Not planned: per-effect script-tag bundles and feature add-ons (more files and registration steps for under 1 KB each).

The `<style data-noisefloor>` is inserted once per root, as the first child of `<head>` or of the shadow root that contains the element at construction, so page and component CSS override it at equal specificity. Rejected for shadow roots: `adoptedStyleSheets`, which cascade after the root's own `<style>` elements and would override component CSS. An element moved into a different shadow root after construction is not restyled; construct after attaching.

The whole stylesheet (all three parts) ships as `dist/style.css` (export `noisefloor/style.css`), generated from the injected string so the two cannot diverge. It exists for a Content-Security-Policy without `'unsafe-inline'` in `style-src`, which blocks the injected `<style>`: the page loads the file and calls `configure({ injectCSS: false })`. A global setting, not a per-instance option, because injection is per root, not per instance. `adoptedStyleSheets` would not help with CSP either, because of the cascade order above. The package's `sideEffects` lists `*.css`, so bundlers keep a bare `import 'noisefloor/style.css'`.

## CSS names

Everything the library injects or sets is prefixed `nf-`: classes (`nf-text*` for Scramble, `nf-img*` for Glitch, shared `nf-scan`, `nf-noscan`, `nf-live`, `nf-lock`), custom properties (`--nf-*`, including the per-glyph and per-line ones, because custom properties inherit from the page) and the `data-nf-wrap` attribute. Attributes read by `noisefloor/auto` are `data-nf` and `data-nf-*`. `--nf-scan-color` sets the scanline colour.

## Site

Sources are plain files in `site/`: `index.html`, `style.css` and `main.js` (a classic script, not a module, so the built page works from `file://`). `scripts/build-site.mjs` writes `site/dist/`: it inlines the HTML-escaped `src/*.ts` files at the `<!--__SRC__-->` placeholder of the source viewer (inlined, not fetched, because `fetch` fails under `file://`) and copies the other files, the media, the fonts and `dist/noisefloor.iife.js`. The page loads the library with `<script src="noisefloor.iife.js">`, the way the docs tell users to.

`npm run typecheck` also checks `main.js` (`site/tsconfig.json`: `checkJs`, with `site/globals.d.ts` typing the `Noisefloor` global from `src/index.ts`), so a renamed method or option, or a wrong option value, fails CI instead of breaking the site. Implicit `any` and null checks are off there: a page script that queries its own markup would need an annotation or assertion on nearly every line, and those errors say nothing about the library. JSDoc annotations cover the library types and the DOM elements whose specific type is used.

- No third-party requests. Chakra Petch (display) and JetBrains Mono (code) are self-hosted in `site/fonts/` (SIL OFL 1.1, licences alongside): the latin and latin-ext subsets as served by Google Fonts, selected by `unicode-range`. Rejected: loading them from Google Fonts (a third-party request on every visit, which sends the visitor's IP to Google and needs extra CSP sources). Running text uses the system UI font, which needs no download and reads better than the display face at body size.

- Sticky menu (Demo, Playground, Get started, API, About, in page order) that is itself the Scramble demo. The link of the section in view gets `aria-current="location"` (scroll handler, no library). The API section has its own sticky sub-menu, one link per entry, marked the same way; each entry is a block whose title sticks under the sub-menu until the next entry. On phones the sub-menu is not sticky, because the site header already wraps.
- Option tables are generated from the library's live `defaults`, so they cannot drift from the code; each is folded in a `<details>` (closed by default).
- Code blocks, the source viewer and the playground snippet are syntax-highlighted by a small in-page tokenizer (comments, strings, whole HTML tags with attribute values as strings, keywords, numbers; colours from the palette variables). Rejected: Prism or highlight.js (third-party code for a handful of snippets we control) and build-time Shiki (heavy, and the playground snippet changes live).
- The Playground section follows the demo. Its settings apply to every effect on the page, stated in a note under its heading; the configuration snippet for the current settings is folded below it (`<details>`, closed). The six control groups fold (`<details>`).
- One playground with one name, closed by default so the first screen stays the demo. Every `[data-pg-toggle]` button (intro, demo stage, Playground section) opens and closes it and says which ("Open playground" / "Close playground", `aria-expanded`). The menu's Playground item stays a plain link to the section, like the other items.
- From 1440 px wide (the 1080 px column plus a 320 px panel) the controls open in a panel on the left, so a setting and its effect on the menu, headline and images are in view together. It pushes the page aside rather than covering it (images resize and Glitch re-measures); Escape or its close button closes it. Its footer has Copy config and Replay demo, which scrolls the demo into view first if needed and replays when the scroll ends (`scrollend`, with a timeout fallback), so the short effects are not over before they are visible. The open state and the panel's open groups are remembered (`localStorage`). Below 1440 px there is no panel, since an overlay would hide the demo being tuned: the controls expand in the Playground section with a sticky preview strip (label and image) that replays on each change, in 3, 2 or 1 fixed columns so no grid cell is empty. The one `#controls` element moves between the two places on a media query listener, so there is never a second copy.
- The skyline sample is drawn procedurally at runtime. The side illustrations are anime-style images by the owner, committed only as reduced 1280 px WebP copies in `site/media/` (full-resolution originals are gitignored) and copied to `site/dist/media/` by the build; the palette preset picks which one is shown, in the side card and the playground preview (Neon, Synth: rooftop; Ice, Phosphor: station; Amber CRT, Redline: market). They are served as files, not inlined: Glitch reads no pixels, so they work even from `file://`. "Load your own image" uses an object URL.
- Head: meta description, canonical URL, Open Graph and Twitter card tags, SVG favicon. The README GIF and the Open Graph image are recorded by `scripts/capture.mjs` rather than by hand, so they can be redone after a visual change: Playwright's fake clock drives timers and `requestAnimationFrame` and `Math.random` is seeded, so frames are evenly spaced and a recording is reproducible (CSS transitions still run on real time). Both use the same composition (menu, demo stage, both images; the intro hidden) at a 1500 px viewport scaled by 0.8, which fits the stack into 1200x630; the GIF (20 fps, 5.6 s loop, 720 px wide, about 1.5 MB) runs ambient micro-glitches and the typed line throughout, with three beats that each pair text with an image so every effect is on screen within a short loop: the headline with the main image, a menu sweep with the side image, then everything at once. The README references the GIF by its absolute Pages URL, because npm does not resolve relative image paths.
- Hosted on GitHub Pages at `https://digitalemagine.github.io/noisefloor/`, deployed by the CI workflow from an Actions artifact of `site/dist`, not from a `gh-pages` branch, so the repository history holds no build output. All site paths are relative, so it works under the `/noisefloor/` subpath. The deploy job runs on `main` of this repository only, so forks do not try to deploy.

## Release

Releases go through `.github/workflows/release.yml` on a `vX.Y.Z` tag that matches `package.json`: the same checks as CI, then `npm stage publish --provenance`, then a draft GitHub release whose notes are that version's `CHANGELOG.md` entry. The version becomes public only when a maintainer approves it with 2FA, and the draft is published after that. npm authentication is trusted publishing (OIDC) from the `npm` environment, with direct publish not allowed, so no long-lived token exists and neither a compromised GitHub account nor a changed workflow can publish on its own; provenance links each version to the commit and workflow that built it. Staged rather than direct, at the cost of one approval per release, as npm recommends.

## Package checks

`npm run check:package` runs `publint --strict` and `@arethetypeswrong/cli` on the packed tarball, then `scripts/treeshake.mjs`, in CI. attw uses the `node16` profile, which skips TypeScript's legacy `node10` resolution (`moduleResolution: "node"`): it cannot resolve subpath exports such as `noisefloor/auto`, and a `typesVersions` shim for a resolution mode TypeScript deprecates is not worth carrying. `style.css` is excluded because it is not a JavaScript entry point.
